# Безопасность

## Границы модели

Relay передаёт непрозрачные байты в локальный MTProxy. Он не расшифровывает MTProto, не заменяет клиентский адаптер и не управляет внешним TLS frontend. HTTPS/WebSocket и обычный публичный сайт не гарантируют нераспознаваемость DPI или доступность заблокированного IP.

## Развёртывание

- Публикуйте только TLS frontend. Relay, MTProxy и admin listener должны оставаться на loopback.
- Используйте собственный статический сайт; одинаковая встроенная страница может быть узнаваемой. Никогда не храните конфиг, ключи или логи в `public_dir`.
- Сохраняйте заголовки bridge: CSP, `Cache-Control: no-store`, `Referrer-Policy`. Не добавляйте несовместимые site-wide CSP/X-Frame-Options.
- Не записывайте query bridge capability, Authorization и WebSocket subprotocol в журналы frontend.
- Храните конфиг с секретом вне Git, с ограниченными правами. Ссылки/QR из `--print-link` также содержат секрет.
- Настраивайте `trusted_proxy_cidrs` только для reverse proxy, который контролирует `X-Forwarded-For`. По умолчанию forwarded headers не доверяются.
- `/readyz` подтверждает TCP-доступность backend, а не MTProto handshake или доступ к Telegram.

## Поведение публичных запросов

Неавторизованные API обслуживаются той же публичной политикой, что обычные пути. С `public_dir` действуют методы и статусы файлового сервиса; без него GET/HEAD получают встроенную страницу, прочие методы — общий 405. Валидная capability открывает bridge только при правильном Host. У API дополнительно проверяется Origin. Формат и ограничения — в [протоколе](docs/protocol.md).

## Сообщения об уязвимостях

Не прикладывайте реальные secrets, bearer-токены, приватные ключи, клиентские IP или полные production-логи к публичному Issue. Для обычного бага используйте синтетический конфиг и минимальное воспроизведение.

Если в GitHub доступен private vulnerability reporting, используйте Security → Report a vulnerability. Если приватный канал не включён, попросите владельца предоставить его, не публикуя детали эксплуатации и credentials. Срок исправления и поддержка старых ревизий пока не гарантируются.
